# Model-assisted .program workflow ideas

This catalog contains 100 design proposals for Unix .program workflows that combine explicit classification-driven control flow with language-model drafting. These are ideas, not runnable programs or evidence that any model adapter exists. Each workflow belongs to .program; the Rust runtime remains a generic interpreter and process runner.

Each idea is one JSON object in its category's JSON array. Fields are id, domain, title, input, cli, classifier, embedding, llm, flow, output, fallback, proof, and complexity. The cli arrays name established Unix tools and adapter roles. No unconfirmed adapter flags or output schemas are invented. The planned execute-model applet exposes manifest tools jev.classify and llm.ask/llm.extract. jev.classify receives a question, allowed labels, a minimum integer percent, and optional fixture/environment-file inputs. llm.ask requires a model and instruction; llm.extract uses a declared schema. The engine still owns the exact fixture-file and emitted-JSON contract, so these ideas do not invent flags or output details.

## Control and safety assumptions

The Unix stage inventories and extracts bounded, identifiable records. A Jev-style classifier proposes a label and a separate signal; .program validates the result and owns every branch. Labels come from an allowlist, and any configured review cutoff is a policy choice, not a claim about model accuracy. An embedding stage, when present, only ranks local references. It cannot classify, approve, or trigger an effect. A generative LLM sees selected evidence and returns a draft or candidate structure. Native tools such as jq, diff, and cmp check shape, citations, and preservation before a report is saved.

Missing adapters, malformed output, unknown labels, weak signals, missing evidence, or failed checks route to a review artifact. Every model stage is exercised with an offline fixture whose expected_request matches the full semantic request and whose provider-native response is parsed through the normal adapter path; fixture runs make no network call. Nothing sends messages, publishes, commits, deletes, or changes source files. Proof criteria assert deterministic interfaces, branch behavior, invariants, and reviewability; none asserts semantic accuracy.

Complexity is a build estimate: M means a bounded pipeline with one model stage and deterministic checks; H means multiple formats, cross-record joins, or several guarded stages. It is not runtime or quality.
