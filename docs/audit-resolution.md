## Architecture recommendations from primary references

1. Use a versioned applet interface as the shared boundary: named inputs, output types/schemas, events, structured errors, declared effects/capabilities, lifetime and compatibility. The WebAssembly Component Model’s WIT precedent supports records, variants, resources, interfaces and import/export worlds. WIT specifies contracts, not behavior, and WASM host imports are not a sandbox for native commands. [WIT reference](https://component-model.bytecodealliance.org/design/wit.html), [worlds and imports](https://component-model.bytecodealliance.org/design/worlds.html), [component composition](https://component-model.bytecodealliance.org/composing-and-distributing/composing.html).
2. Keep transport framing distinct from semantic type contracts. Current MCP is a useful primary source for one concrete request/stream binding, not an applet ABI: JSON-RPC stdio is newline framed; Streamable HTTP is per-request POST/JSON or SSE; cancellation, versioning and security vary by binding. The July 2026 HTTP revision has no sessions or resumable SSE, so reconnection and durable delivery still need an explicit contract. [Transport overview](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports), [stdio](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio), [Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http), [2026 revision and compatibility shift](https://blog.modelcontextprotocol.io/posts/2026-07-28/).
3. Define task scopes so children cannot outlive their owner, specify all/race/join behavior and sibling-failure policy, and treat cancellation as cooperative unless the OS backend proves process termination. Swift’s primary structured-concurrency docs are a useful semantic reference, not a Rust API recommendation. [Swift structured-concurrency proposal](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0304-structured-concurrency.md).
4. Treat effect/capability declarations as inputs to policy, not evidence that an executable is truthful or safe. Bubblewrap explicitly delegates policy security to the argument-construction layer; Apple’s `sandbox-exec` command is deprecated. WIT import boundaries are useful for WASM components, but do not generalize that guarantee to host processes. [Bubblewrap security](https://github.com/containers/bubblewrap#sandbox-security), [macOS sandbox-exec manual](https://man.freebsd.org/cgi/man.cgi?manpath=macOS+13.6.5&query=sandbox-exec&sektion=1).
5. Replace universal exactly-once language with scoped idempotency/transaction-participant semantics and explicit unknown outcomes. Google’s exactly-once delivery is region and pull-subscription scoped; AWS describes retries made safe through idempotency tokens honored by the endpoint. [Google Pub/Sub exactly-once](https://docs.cloud.google.com/pubsub/docs/exactly-once-delivery), [AWS idempotent APIs](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/).
6. Quickshell’s QML properties/signals are typed and reactive, but a bridge still needs thread/event delivery, object lifetime, cancellation, restart and failure rules. [Quickshell QML language](https://quickshell.org/docs/v0.3.0/guide/qml-language/).

## Cross-lane standards and scope checks

**LSP 3.17:** the server owner pins the candidate to LSP 3.17 over stdio. The upstream spec uses CRLF ASCII headers, `Content-Length` in body bytes, UTF-8 JSON-RPC, and zero-based positions with negotiated position encoding; UTF-16 must be supported and is the default. The implementation intentionally covers a subset (same-file reusable-program symbols) and has hard bounds. [LSP 3.17 base protocol](https://github.com/Microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/specification.md), [position encoding](https://github.com/Microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/types/position.md).

**Service managers:** generated units are review-only. systemd `KillMode=control-group` stops remaining processes in the unit cgroup, with configured TERM/KILL timing; this is distinct from interactive shell job control and does not prove behavior on an unpinned target systemd release. Candidate units are per-user; launchd uses ProgramArguments/KeepAlive but provides no systemd cgroup guarantee. [systemd.kill](https://github.com/systemd/systemd/blob/main/man/systemd.kill.xml), [systemd.service](https://github.com/systemd/systemd/blob/main/man/systemd.service.xml), [Apple launchd guide](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html).

**HTTP and event cursors:** RFC 9110 §9.2.2 says clients should not automatically retry a non-idempotent request unless they can establish idempotent semantics or know the original was not applied. The IETF Idempotency-Key header draft is expired and archived as of 2026-10-14, so the candidate must not imply that its endpoint-specific key/scope is a universal HTTP behavior; the server must durably honor the contract. WHATWG EventSource resends `Last-Event-ID` on reconnect; that cursor alone does not atomically acknowledge an external effect with consumer state. Candidate `execute.applet/1` sends POST once and exposes duplicate cursors rather than promising exactly once. [RFC 9110 §9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2), [IETF Idempotency-Key draft status](https://datatracker.ietf.org/doc/draft-ietf-httpapi-idempotency-key-header/), [WHATWG Last-Event-ID](https://html.spec.whatwg.org/multipage/server-sent-events.html#the-last-event-id-header).

**Filesystem atomicity and durability:** POSIX.1-2024 rename semantics describe atomic directory-entry visibility, while its filesystem-cache rationale warns that directory operations may not be durable across a crash and may require syncing parent directories (two if both are affected). Candidate transaction recovery therefore provides bounded per-file reconciliation/compensation, not an all-files atomic commit or universal power-loss guarantee. Windows parent-directory sync is currently a no-op; same-user journal checksums are not authentication. [POSIX rename](https://pubs.opengroup.org/onlinepubs/9799919799/functions/rename.html), [POSIX.1-2024 filesystem-cache rationale §A.4.11](https://pubs.opengroup.org/onlinepubs/9799919799/xrat/V4_xbd_chap01.html).

**JSONC compatibility:** no VS Code `jsonc-parser` compatibility is claimed. That library documents tolerant parse/error reporting and generic object/array path edits; candidate Rust JSONC code instead rejects malformed documents and edits active top-level object keys only. If compatibility becomes a requirement, pin a package version and compare against a golden corpus. [Microsoft node-jsonc-parser](https://github.com/microsoft/node-jsonc-parser).

## Honest closure rules

- A locally passing test closes only the behavior it directly asserts on the tested platform and exact source.
- Schema presence is not contract compatibility; effect metadata is not an enforced OS capability; `sandbox_required` preflight is not a sandbox security certification.
- Fake Omarchy backends do not certify Quickshell/Hyprland/Wayland sessions. Ubuntu CI does not certify Arch or Omarchy.
- A package helper test does not establish install/update/rollback success in a clean deployment.
- Historical benchmark wins do not prove global speed superiority or AI productivity; held-out tasks and paired, raw measurements are needed.
- Exactly-once claims must name the participant system, durable key/transaction, crash model and acknowledgement boundary. Unknown external outcome must remain representable.
